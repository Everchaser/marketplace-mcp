# marketplace-mcp

Read-only MCP-сервер для поиска и сравнения товаров в **Яндекс Маркете** (RUB) и **VARUS** (UAH). Работает через stdio: его запускает ваш MCP-клиент. Сервер не оформляет заказы и не резервирует товары.

Три инструмента: `search` — поиск, `get_card` — карточка товара, `get_cards` — проверка списка товаров. Для VARUS доступны цены и наличие по магазинам, поиск недостающих позиций на соседних точках и приблизительная стоимость списка покупок.

## Установка

Нужны Git, [uv](https://docs.astral.sh/uv/) и Python 3.12 (uv может установить его при синхронизации).

```bash
git clone https://github.com/everchaser/marketplace-mcp.git
cd marketplace-mcp
uv sync --locked --python 3.12
```

## Подключение к MCP-клиенту

Добавьте сервер в настройки клиента. Пример для клиентов, использующих раздел `mcpServers`:

```json
{
  "mcpServers": {
    "shopping": {
      "command": "/absolute/path/marketplace-mcp/.venv/bin/python",
      "args": ["-m", "marketplace_mcp"]
    }
  }
}
```

Замените `/absolute/path/marketplace-mcp` на путь к клонированному проекту. Формат настроек зависит от клиента; для долгих пакетных проверок рекомендуемый таймаут — 360 секунд. Отдельный HTTP-сервис или systemd-служба не нужны.

Проверить доступные параметры запуска:

```bash
.venv/bin/python -m marketplace_mcp --help
```

### Подключение к Hermes Agent

Команды ниже рассчитаны на Linux, macOS или WSL. Выполняйте их **на той машине, где работает Hermes**, из каталога `marketplace-mcp`, после установки зависимостей через `uv sync`. Hermes сам запускает MCP как дочерний процесс; отдельно запускать сервер не нужно.

1. Зарегистрируйте локальный сервер и задайте таймаут для пакетных проверок:

   ```bash
   hermes mcp add shopping \
     --command "$PWD/.venv/bin/python" \
     --connect-timeout 30 \
     --args -m marketplace_mcp
   hermes config set mcp_servers.shopping.timeout 360
   ```

   `--args` должен быть последней опцией команды добавления. Если Hermes предложит выбрать инструменты, оставьте включёнными все три: `search`, `get_card`, `get_cards`. Если имя `shopping` уже занято другим сервером, выберите другое и замените его во всех командах этой инструкции.

   `$PWD` подставляет абсолютный путь к текущему каталогу. После подключения не перемещайте проект: при смене пути потребуется обновить `mcp_servers.shopping.command` через `hermes config set`.

2. Проверьте подключение:

   ```bash
   hermes mcp test shopping
   ```

   При успешной проверке сервер должен предоставить инструменты `search`, `get_card` и `get_cards`. Эта проверка подтверждает подключение и обнаружение инструментов, но не доступность сайтов маркетплейсов.

3. В открытом чате Hermes выполните `/reload-mcp` или перезапустите Hermes. Затем попросите, например: «Найди на Яндекс Маркете беспроводные наушники и сравни цены и отзывы».

Для Яндекс Маркета дополнительных настроек местоположения не нужно. Для VARUS сначала настройте координаты по инструкции ниже; после изменения файла настроек также выполните `/reload-mcp`.

Обычное подключение не требует `--nic`: этот параметр нужен только для явной привязки запросов Яндекс Маркета к сетевому интерфейсу на Linux. Не копируйте имя интерфейса с чужой машины.

Подробнее о MCP-клиенте: [официальная документация Hermes Agent](https://hermes-agent.nousresearch.com/docs/user-guide/features/mcp).

## Настройка VARUS

Для Яндекс Маркета местоположение не требуется. Для VARUS создайте файл `~/.config/shopping/settings.json` (или `$XDG_CONFIG_HOME/shopping/settings.json`, если эта переменная задана):

```json
{
  "varus": {
    "coordinates": {"lat": 48.4015236, "lon": 35.030697},
    "geocoder": "disabled"
  }
}
```

Это пример координат публичного магазина на вул. Панікахи, 15 в Днепре. Замените их своими координатами; без настройки местоположения запросы к VARUS завершатся ошибкой. Домашний адрес вводить не нужно: геокодирование в примере отключено.

Другой путь к файлу можно передать в аргументах сервера: `--settings /absolute/path/settings.json`. После изменения настроек перезапустите подключение MCP в клиенте.

## Использование

После подключения попросите своего агента, например:

- «Найди в VARUS ягодный джем в наличии рядом со мной».
- «Проверь наличие этих товаров и прикинь стоимость списка покупок».
- «Найди на Яндекс Маркете варианты и сравни цены и отзывы».

В VARUS одиночная карточка проверяется в ближайшем магазине. Пакетная проверка ищет недостающие товары также максимум в трёх соседних магазинах. Расстояния считаются по прямой, а не по маршруту.

Наличие и цены могут устаревать; точное количество, доставка и резерв не гарантируются. Состав и БЖУ могут отсутствовать. Поиск VARUS сопоставляет слова в названии, поэтому при пустой выдаче полезны более короткий запрос или украинское название. Отзывы VARUS не извлекаются; отзывы Яндекса — только доступная выборка. Если сайт изменит разметку или ограничит доступ, возможны ошибки извлечения.

## Сеть и обновление

Обычный запуск использует сеть хоста. На Linux для запросов **только к Яндекс Маркету** можно добавить аргументы `--nic ИМЯ_ИНТЕРФЕЙСА`: они привязывают соединения к выбранному физическому интерфейсу. VARUS продолжает использовать обычный маршрут; настройки VPN и DNS не меняются. При ошибке привязки скрытого переключения на другой маршрут нет. Подробности — в [AGENTS.md](AGENTS.md).

Обновление из каталога проекта:

```bash
git pull --ff-only
uv sync --locked --python 3.12
```

Затем перезапустите MCP-подключение в клиенте.
